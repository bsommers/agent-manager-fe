<objective>
Replace the single-class socket (silent permanent fallback to mock, no reconnect, unguarded JSON.parse) with a layered transport: `Transport` (connect, backoff, heartbeat, states) under a `WsAdapter`, a separate `MockAdapter` for explicit Demo mode, a `connectionStore` the UI can read, and a thin `agentSocket` shim that keeps today's API (INT-01).

Purpose: a dropped socket must look dropped, and recover on its own. Today an error or close flips to mock mode forever and the user sees fake output believing it is live (gap G1, concerns "Silent fallback to mock mode").
Output: services, store and tests; the visible chip and banner are built by plan 03-02 on top of this store.

Contract anchors (docs/superpowers/specs/2026-11-07-fe-be-contract.md): section 2.2 states, 2.3 reconnect policy, 2.4 heartbeat (ping every 15 s of silence, 10 s to answer), 2.6 close code 4401, section 1 environment variables. The BackendAdapter here is the transport-level surface (connect, disconnect, state and message subscription, send); lifecycle methods are added to it by Phase 6 and Phase 12 per spec section 14.

This plan supersedes the dual-mode fallback decision of ADR-005; the ADR text is updated in plan 03-02.
</objective>

  <behavior>
    - computeDelay(attempt, config, random) returns floor(random * min(capMs, baseMs * factor^attempt)); with random fixed at 1 the ceilings for attempts 0..6 are 500, 1000, 2000, 4000, 8000, 15000, 15000; with random fixed at 0 every delay is 0; default config is baseMs 500, factor 2, capMs 15000
    - an unexpected close (any code except 4401 or a deliberate close()) moves to reconnecting with attempt incremented, nextRetryAt = now + computed delay and lastError describing the close; when the timer fires a new socket is created; opening it reports open; the first inbound frame resets attempt to 0
    - consecutive failed attempts use the growing ceilings above (test with random fixed at 1 and fake timers advancing exactly each delay)
    - maxRetries: when attempt exceeds it the state becomes closed with lastError "retry limit reached" and no timer or socket remains
    - close code 4401 reports auth_failed with no retry and no pending timers
    - heartbeat (intervalMs 15000, timeoutMs 10000, configurable): after intervalMs without any inbound frame a ping frame {"type":"ping","t":<now>} is sent; any inbound frame cancels the pending timeout and restarts the idle timer; if timeoutMs passes after a ping with no inbound frame the socket is abandoned (handlers detached, close attempted inside try/catch) and the unexpected-close path runs; heartbeat can be disabled with false
    - reconnectNow(): from reconnecting or closed it cancels any pending timer, resets attempt to 0 and connects at once; from open it is a no-op
    - close() after reconnect scheduling cancels the timer; no socket events or timers survive (vi.getTimerCount() is 0)
    - WsAdapter forwards reconnectNow and disconnect to the transport and keeps malformedFrames across reconnects
  </behavior>
