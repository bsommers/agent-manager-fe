# Phase 09.1 Plan 03: killSession gateway half Summary

`agent:kill {agentId, killSession: true, confirm: true}` now ends a known tmux agent's session through a shell-free `execFile` call (`tmux kill-session -t =<name>`) and removes the agent in one snapshot; without `confirm` exactly `true` the gateway refuses with a typed `agent:error` USAGE to the requester and runs nothing. Plain close is unchanged and leaves the tmux session running.

## What was built
- `tmuxKill.ts`: `TMUX_SESSION_NAME_RE`, `isKillableTmuxSessionName`, `tmuxSessionNameOf`, `killTmuxSession(name, run?)` (5 s timeout, no shell option, stderr classification: session/server missing counts as `already_gone`).
- `SessionManager`: `handleClientMessage(msg, reply?)`; confirm gate first; UNSUPPORTED for non-tmux, USAGE for unkillable name, INTERNAL (fixed text, no stderr) for tmux failure; per-agent in-flight de-dup; driver exit held back during a kill and replayed only if the kill fails; session-name derivation shared with the drivers via `tmuxSessionNameOf`.
- `server/src/index.ts`: one reply callback writing to the requesting socket only.
- Protocol: type fields, validator row (optional booleans), 3 client + 2 invalid fixtures, validator tests; spec table row, semantics paragraph and reconciliation row 17; README and ARCHITECTURE updated.
