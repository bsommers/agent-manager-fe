QA BUG 3, UI half (QA-03): closing an agent must NOT kill its tmux session (that is correct and unchanged); add an explicit "Kill tmux session..." control that goes through `DestructiveSafetyModal`, document the manual alternative, and update the QA plan and Playwright driver so step 12b expects the session to survive closing and a new step kills it through the new control.

Protocol and safety (decided in 09.1-03, summarised): the wire message is `agent:kill {agentId, killSession: true, confirm: true}`; the gateway derives the session name from its own registry, uses execFile with an argument array and a strict name check, and refuses a kill without `confirm: true` with a typed `agent:error`. This plan is the UX that sets `confirm`: the modal's Confirm button is the only code path that passes it. The store does not default or fabricate `confirm`, so a caller that forgets it is stopped by the gateway, not by the browser.

Scope kept small: one footer control in `AgentControls`, local confirmation state (no new overlay kind in `uiStore`, so `App.tsx`, `Header.tsx` and `Toolbar.tsx` stay untouched), two optional props on the modal's copy, one options argument on `removeAgent`. The FE does not yet handle `agent:error` frames (Phase 6 and 9), so a refused or failed kill is reported by the existing 10 s "not confirmed" notice, reworded for the session kill. No command-palette entry (the palette's command set is 05-02's and the confirmation lives in the pane).
