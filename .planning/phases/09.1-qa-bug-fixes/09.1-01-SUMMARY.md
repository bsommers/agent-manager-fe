# Phase 09.1 Plan 01: xterm query-reply suppression Summary

xterm.js no longer types its own answers (DA1, DA2, colour, status, mode, DCS replies) into the shell; query handlers on `term.parser` consume the queries, and real keystrokes, paste and application-requested focus reports still reach `agent:input`.

## Deviations from Plan

1. **[Rule 1 - plan fact wrong] custom `CSI t` handlers are gated by windowOptions.** xterm's public parser wraps custom `CSI Ps t` handlers so they run only for operations enabled in `windowOptions` (otherwise swallowed). The setter-probe test for CSI 22/23 t therefore builds its terminal with `windowOptions` enabled. Behaviour is safe either way: with defaults xterm emits no window reports, with them enabled the guard consumes the reporting ops.
2. **Environment:** the worktree had no `node_modules`; symlinked the main checkout's (root and `server/`), gitignored, not committed.
3. **Focus test:** xterm reports current focus state when mode 1004 is enabled; the test clears that initial report before asserting later focus and blur transitions.
4. **Formatting:** new files formatted with prettier (single quote, width 120) to match the repo style.

None else; plan executed as written.
