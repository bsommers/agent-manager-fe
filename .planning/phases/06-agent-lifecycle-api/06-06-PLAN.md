<objective>
INT-03 and GW-04 HTTP half (Phase 6 criterion 6): add the first HTTP surface of the gateway, `/api/health` and `/api/agents` (GET, POST, DELETE), as a thin wrapper over the service layer of 06-01 and the dispatch path of 06-02. The service layer existed before any route was written, as criterion 1 requires, and the router contains no agent logic: validation is the package validator, execution is `AgentApi.execute`, idempotency is the shared reqId cache, and error status codes come from `ERROR_HTTP_STATUS`.

Locked decisions honoured (docs/CHECKPOINT.md): closing an agent never kills tmux (DELETE /api/agents/:id is the catalog's `agent.close`; the tmux-ending HTTP form is added by plan 06-07 with the catalog-driven confirm policy, and until then there is no HTTP route that can kill a session); the gateway enforces destructive operations (nothing destructive is reachable here); port 8088 belongs to the user's nginx and is not touched (tests bind port 0, nothing in the docs asks anyone to move or stop nginx); no token in a URL (the only identifier carried in a header is the idempotency key, and auth is Phase 8).

Design decisions made here:
- Routes are exactly the catalog's HTTP bindings (`listHttpRoutes()`) plus the exempt liveness probe `GET /api/health`. Catalog routes that later phases implement (`GET /api/agents/:id/logs`, `GET /api/search`) answer `UNSUPPORTED` (422) instead of a bare 404 so a client can tell "not in this build" from "no such path"; a coverage test ties the router to the catalog in both directions.
- POST body = the `agent:create` fields; `Idempotency-Key` header = `reqId` (a body `reqId` is ignored: the header is the contract, spec section 7). The router builds `{ ...body, type: 'agent:create', reqId }`, runs `parseClientMessage`, and converts a failed parse with `rejectionFor` from 06-02 (so field-name-only messages and the `PAYLOAD_TOO_LARGE` mapping are identical on both surfaces).
- `/api/health` reports `contract` (CONTRACT_VERSION), `epoch` (a per-process random id, `randomUUID`, injectable through `BootstrapOptions.epoch` for tests; Phase 11 replaces it with the log-store generation), `backends: [{ id: 'local', up: true }]` (the in-repo tmux and ssh drivers form one local backend until Phase 19 and 20 introduce adapters) and `agents` (integer count; auth does not exist yet, so it is always present).
- CORS is deliberately absent: the FE talks to the gateway over WebSocket. The first browser consumer of these routes (Phase 16 search) must add a CORS policy with the same allowlist; recorded in the README.

Reversibility: `reversible` (a new mounted router; git revert removes it; the catalog and wire messages are unchanged).

Coverage (source audit): GOAL (list, create, close over HTTP), success criteria 1 (handlers thin over the service, before any route: satisfied by ordering 06-01 then this plan) and 6 (`/api/health` and `/api/agents` GET, POST, DELETE; repeated reqId idempotent over HTTP) are covered here; REQ INT-03 and GW-04 (HTTP wrapper). Not planned: the HTTP form of `agent.kill` and the destructive policy (06-07), `/api/agents/:id/logs` and `/api/search` (Phases 11 and 16), authentication and Host-header checks (Phase 8), rate limits (Phase 12), CORS (Phase 16), an MCP handler (Phase 21.1).
</objective>

Facts the tasks rely on:
- `bootstrap(port, host, options)` builds the Express app, the origin allowlist as a `Set` of normalized origins (trailing slashes removed), the WebSocket server and the SessionManager (`sessionManager.api` is the AgentApi from 06-02; `sessionManager.service` the AgentService from 06-01). It registers the legacy `GET /health` and returns `{ app, server, wss, sessionManager }`. `BootstrapOptions` currently has `allowedOrigins` and `heartbeatMs`.
- `AgentApi.execute(msg)` returns `{ ok: true, ack?: { op, agent? } }` or `{ ok: false, error }` where `error` is a ServiceError (`code`, fixed `message`, `retryable`, optional `agentId`); the ack agent is present for create and update even when no reqId was sent (it is what the HTTP 201 body needs). The idempotency cache lives inside AgentApi, shared by every surface that calls execute.
- `ERROR_HTTP_STATUS` maps USAGE 400, UNAUTHENTICATED 401, FORBIDDEN 403, NOT_FOUND 404, CONFLICT 409, UNSUPPORTED 422, PAYLOAD_TOO_LARGE 413, RATE_LIMITED 429, INTERNAL 500, BACKEND_DOWN 503, TIMEOUT 504. `parseHttpBody(kind, body)` validates the kinds health, agents, agent, ok, logs, search, error. `listHttpRoutes()` currently returns ids `DELETE /api/agents/:id`, `GET /api/agents`, `GET /api/agents/:id/logs`, `GET /api/search`, `POST /api/agents`; `UNCATALOGUED_HTTP_ROUTES` is `GET /health` and `GET /api/health`; `checkSurfaceCoverage(surface, listed, exempt)` compares a surface's identities with the catalog.
- `rejectionFor(raw, failure)` (06-02) returns a USAGE or PAYLOAD_TOO_LARGE `agent:error` frame with a field-name-only message, or null for an unknown type.
- The contract (section 7): POST requires `Content-Type: application/json` and an Origin that passes the allowlist when the header is present; success bodies carry `"ok": true`; cookies are never used. Express sends `X-Powered-By` unless disabled.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser page / local process -> HTTP API | Any process on the machine, and any web page the user visits, can send requests to the loopback port |
| request path, header and body -> router | Untrusted strings become a validated client message |
| internal error -> HTTP response | Framework and service errors must not leak |
