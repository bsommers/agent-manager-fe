<objective>
GW-04, first half: create the gateway agent service layer before any HTTP route exists. Today `SessionManager` mixes four jobs: the WebSocket client set, the agent registry, the driver lifecycle and the message switch (including the 09.1-03 session-kill flow). This plan moves the registry, the drivers and every agent operation into a transport-agnostic `AgentService` that returns typed results, and shrinks `SessionManager` to the client set, the snapshot on connect, the fan-out broadcast and a legacy message mapping. It is a behavior-preserving move first (the 208 existing server tests must pass unedited), followed by the capabilities the later plans need (typed spawn failure without a ghost agent, update, per-target broadcast results, an agent cap).

Locked decisions (docs/CHECKPOINT.md, honoured here): the service layer comes first and needs no catalog; closing an agent must not kill tmux (close and destroy stay two methods, and only destroy touches tmux); the gateway enforces destructive operations, not just the FE modal (the confirm gate stays inside destroy and is tested without a handler); port 8088 belongs to the user's nginx and is not touched (tests bind port 0); no token in a URL (nothing here touches URLs).

What this plan deliberately does NOT change (so it can be reviewed as a move): the WS wire behavior (the full `agent:init_list` snapshot after create and close, the silent handling of an unknown id, the typed replies of the kill-session path), `server/src/index.ts`, any protocol package file, and any frontend file. 06-02 puts one validated dispatch path with `reqId` acks in front of the service and 06-04 replaces the post-mutation snapshots with `agent:added/removed`.

Design (per the repo conventions, level 0 discovery: no registry package, only Node and existing modules):
- `serviceResult.ts`: `ServiceError { code: ErrorCode; message: string; retryable: boolean; agentId?: string }`, `ServiceResult<T> = { ok: true; value: T } | { ok: false; error: ServiceError }`, helpers `ok(value)` and `fail(code, message, { retryable?, agentId? })` (retryable defaults to `isRetryableByDefault(code)`), and `errorFrame(error, reqId?)` which builds the `agent:error` frame (agentId and reqId included only when they are strings of 1 to 128 characters, `retryable` copied, no `detail`). `errorFrame` replaces the private `refuse` frame builder of SessionManager so every WS reply is built in one place.
- `AgentService`: constructor takes `publish: (msg: WSMessageServer) => void` and an options object `{ maxAgents?: number }` (default `LIMITS.MAX_AGENTS`). Methods: `initialize(): Promise<void>`, `list()`, `get(id)`, `count()`, `driverOf(id)`, `create(input)`, `close(agentId)`, `destroy(agentId, { confirm })` (async), `input(agentId, data)`, `resize(agentId, cols, rows)`, `broadcast(targetIds, data)`, `update(agentId, patch)`. The registry, the driver map and the in-flight session-kill map move here; the driver exit handling (deferred while a kill is in flight, dropped for an agent no longer registered) moves with them. The log lines of the 09.1-03 flow keep their exact formats (one warning per refusal, one error per tmux failure, one audit line per success) because existing tests count them.
- `SessionManager`: keeps `addClient` (sends the snapshot), `removeClient`, `broadcast`, `handleClientMessage(msg, reply?)` (a switch that calls the service and, for destroy refusals, replies with `errorFrame`) and the legacy public methods used by the tests (`createAgent`, `killAgent`, `sendInput`, `resizeSession`, `getAgentCount`, `getAgents`, `getAgent`, `getDriver`, `initialize`), all delegating. It gains a readonly `service` property that later plans use.
- Legacy shims (documented, removed by 06-02): the service answers an unknown id with a typed NOT_FOUND, while the pre-Phase-6 WS behavior for an unknown id on a kill is an unchanged snapshot to every client; SessionManager reproduces that snapshot when the service says NOT_FOUND so no pinned test changes.

Reversibility: internal refactor behind unchanged behavior; `reversible` (git revert restores the old class).

Coverage (source audit): GOAL (service layer first, handlers thin) and REQ GW-04 are covered here (first half; 06-02 and 06-06 add the WS and HTTP wrappers). Not planned here, by design: `reqId`/ack/idempotency (06-02), `agent:added/removed` (06-04), HTTP (06-06), catalog-driven destructive policy (06-07), broadcast acks and rate limits (Phase 12), an MCP handler (Phase 21.1).
</objective>
