<objective>
INT-03 frontend half 1 (criteria 2 and 3 of Phase 6, and the FE handling of `agent:error` named in docs/CHECKPOINT.md): the UI stops guessing which snapshot entry is its own create and instead correlates every lifecycle request with its answer by `reqId`. Create, kill and update resolve with the server's agent or reject with a typed error, with a 10 s local timeout; a refused kill shows its real reason at once; an `agent:error` that belongs to no request becomes a visible notice.

Locked decisions honoured (docs/CHECKPOINT.md): closing an agent never kills tmux (close stays the plain `agent:kill`; the session kill still sends `killSession` plus `confirm` only from the DestructiveSafetyModal flow, unchanged and never invented by the store); the gateway enforces destructive operations, so the FE only forwards what it was given; port 8088 and the user's nginx are untouched; no token in a URL (nothing here builds URLs). Demo mode is untouched.

Contract dependency, not a plan dependency: this plan implements section 6.1 and the `agent:ack`/`agent:error` rows of the contract spec against the existing package types and validators. The gateway half is plan 06-02 in the same wave (disjoint files: `src/**` here, `server/**` there). Until 06-02 is merged a Phase-10 gateway never acks, so the pair must merge together; the merge gate and the manual QA run after both. Roster announcements by `agent:added/removed/updated`, reconnect resync tests and the documentation are plan 06-05 (wave 9); this plan still reconciles with the full `agent:init_list` snapshot exactly as today, except that `reconcileSnapshot` no longer claims pending creates by name, mode and targetHost (pending panes are preserved untouched until their answer settles them).

Design (level 0 discovery: no package; `crypto` is a platform API):
- `agentRequests.ts` exports `REQUEST_TIMEOUT_MS = 10000`, `AgentRequestError` (an `Error` subclass with `code: ErrorCode | 'NOT_CONNECTED'`, `retryable`, `reqId`, optional `agentId`), `newReqId()` (crypto.randomUUID when it exists, else a UUID v4 built from crypto.getRandomValues, which works on plain-http LAN origins where randomUUID is undefined; a last-resort Math.random fallback because a reqId is a correlation key, not a secret) and the `AgentRequests` class. Constructor deps: `send(msg): boolean`, optional `timeoutMs`, `maxTransmissions` (3), `newReqId`, `setTimer`/`clearTimer`. `request(build)` generates the reqId, builds the frame with it, sends once and returns `{ reqId, promise }`; when `send` returns false it throws `AgentRequestError('NOT_CONNECTED')` synchronously and keeps nothing (so the store can keep today's synchronous "not connected" notice). `handleServerMessage(msg)` returns `'consumed'` for an `agent:ack` or `agent:error` whose reqId is in flight or was settled in the last 64 requests (late answers after a timeout must not become stray notices) and `'ignored'` otherwise. `resendInFlight()` re-sends every in-flight frame unchanged and restarts its timer, up to the transmission cap. `clear()` drops all entries and timers without rejecting (tests), `dispose()` rejects all in flight with NOT_CONNECTED. Every timer is cleared on settle.
- `AgentSocketService` gains a readonly `requests` built with `send: (m) => this.send(m)` (late-bound so `vi.spyOn(agentSocket, 'send')` in existing tests keeps intercepting), a public `request(build)`, offers each message to `requests.handleServerMessage` first in `notify`, calls `resendInFlight()` when the adapter state changes to `open` from any other state, and disposes the layer in `dispose()`.
- Store: `PendingCreate` keeps its fields and gains an optional `reqId` (optional so the four component and keyboard test files that build `pending` entries by hand compile unchanged). `reconcileSnapshot` keeps its signature but loses the claiming logic and the claim-map result field: it replaces by id, keeps local layout and unreadOutput, preserves pending panes in place, drops agents the snapshot no longer lists (reported in `removedIds`), appends fresh agents and collapses duplicate ids. The per-request store timers (`armRequestTimer`, `requestTimers`) are removed: timeouts belong to the request layer. `ROSTER_REQUEST_TIMEOUT_MS` stays exported (same value) for existing imports.

Reversibility: `reversible` (additive request layer; wire messages are unchanged; git revert restores key-based claiming). The roadmap's "reqId is required" is satisfied on the FE by always sending it (asserted in tests); the wire field stays optional (06-02 objective).

Coverage (source audit): GOAL, success criteria 2 (FE half: promise API, typed rejection, 10 s timeout) and 3 (reqId replaces name/mode/targetHost reconciliation) and the FE handling of `agent:error` are covered here; REQ INT-03 (FE half). `agent:added/removed/updated` handling and the reconnect-without-duplicates proof are 06-05; documentation of the reqId flow is also 06-05 (so the docs describe the final state once). Not planned: a rename/tags/group UI (UX-02 stays open for the Phase 10 remainder; this plan only provides `updateAgent`), typed failure toasts with per-code design (Phase 9, UX-01), broadcast acks (Phase 12).
</objective>
