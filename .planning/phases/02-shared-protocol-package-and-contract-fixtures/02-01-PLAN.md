<objective>
Create the shared wire-contract package `packages/protocol` (`@agent-manager/protocol`), move the existing wire types into it, make both the frontend and the server consume it, and add runtime validators for the eight messages that exist today (INT-08, first slice).

Purpose: the FE currently reaches into `server/src` for its types, which couples the build to one backend and blocks multi-backend work. The contract spec (docs/superpowers/specs/2026-11-07-fe-be-contract.md, section 13) fixes the package as the single source of truth.
Output: the package, rewired consumers, validators with tests.

Decisions applied: validators are hand-written and table-driven, and no registry package is added (planner constraint: no package legitimacy audit exists for this phase); the install step only links a local path.
</objective>

In validate.ts export the ParseResult type: a success object (ok true, msg) or a failure object (ok false, reason one of not_object, missing_type, unknown_type, invalid_field, plus optional field and a detail string). Implement a small internal field-spec vocabulary (string with min/max length and optional control-character ban, integer with range, finite number, boolean, enum, string array with bounds, object-array validated by a nested spec) and two tables, one per direction, keyed by message type and declared with the TypeScript satisfies operator against a Record keyed by the type literal of WSMessageClient and WSMessageServer so that adding or removing a union member without a table row is a compile error. A single generic function walks a table row, reads only the declared keys into a fresh plain object (never copies unknown keys), and returns the result. Wrap the whole parse in try/catch. Compute UTF-8 byte length with a small pure function over code points (no TextEncoder, so the package type-checks without DOM or Node lib types). Export parseClientMessage, parseServerMessage and parseAgent from the barrel.
