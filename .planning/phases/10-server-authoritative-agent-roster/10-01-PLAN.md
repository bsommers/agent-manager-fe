<objective>
Make the agent roster in live mode follow the gateway instead of the browser (UX-02, success criteria 1 and 2 plus the status-badge part of 3): Add Agent really sends `agent:create`, the pane is honest while it waits, and the roster is whatever the gateway last announced.

Purpose: manual QA step 1 (docs/qa-test-plan.md section 5) fails today because `addAgent` in `src/store/agentStore.ts` only builds a local agent and starts the mock stream; it never sends `agent:create`, and the gateway's own agent (with its own id) is never shown. Phase 10 is pulled forward on 2026-11-07 as a slice ahead of its declared dependencies Phase 6 and Phase 8, so this plan works against what the gateway emits today: it announces every create, kill and new connection as a full `agent:init_list` snapshot to all clients (`server/src/services/SessionManager.ts`: `createAgent`, `killAgent`, `addClient`) and it assigns its own id. The plan therefore treats `agent:init_list` as the idempotent full snapshot the contract spec section 2.5 already defines, and reconciles a pending create to the server agent by matching name, mode and targetHost against agents that were not in the roster before.

Output: `src/store/rosterReconcile.ts` (new), changes to `src/store/agentStore.ts`, `src/services/agentSocket.ts`, `NotificationToastManager.tsx`, `AgentPane.tsx`, `Workspace.tsx`, and tests for each. No server source change and no change to `packages/protocol/**`, root `package.json`, lockfiles, `vite.config.ts` or `.github/**`. Plan 10-02 (parallel, disjoint files) pins the gateway behavior this plan relies on and updates the docs.

Deferred, deliberately not in this plan (each stays open in the roadmap):
- Auth and secure transport: Phase 8 (the gateway needs no `hello` today).
- `reqId` correlation, `agent:ack`/`agent:error` typed errors, `agent:added/removed/updated`, HTTP `/api/agents`, validators at the gateway dispatch: Phase 6. The key-based reconciliation here is replaced by `reqId` correlation then.
- Rename, tags and group through `agent:update`: the gateway's `handleClientMessage` has no `agent:update` case (it ignores the message), so no UI is built for it; Phase 6 adds server support and the UI.
- Stale-agent markers: they need new server fields (Phase 6/11).
- Typed failure toasts, pane connection states, error boundary: Phase 9 (this plan shows only a plain error notice).
- An initial-command input in the Add Agent modal: `addAgent` accepts and forwards `initialCmd`, but the modal gets no new field.

Known limits accepted for this slice: BroadcastBar counts a pending pane as a target until it is confirmed (a broadcast to the temporary id is a no-op on the gateway); if the gateway fails to spawn the driver it registers the agent without announcing it, so a ghost agent can appear in a later snapshot (Phase 6 typed create errors fix this server-side); initial terminal output that arrives before the new pane mounts is replayed only by the terminal redraw triggered by the pane's first resize (full replay is Phase 11).

Coverage (source audit): GOAL (roster reflects backend truth) covered by tasks 1-3; REQ UX-02 partly covered (empty live start, pending/confirmed create, status badge; stale markers and rename/tags/group deferred above); no RESEARCH.md or CONTEXT.md exists for this phase, the scope is the 2026-11-07 request that pulled it forward; no registry package is added (Level 0 discovery: existing patterns only).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| gateway -> FE roster | agent:init_list payloads and status events are untrusted input that become React state and visible text |
| FE -> gateway | agent:create / agent:kill requests built from user-typed values |
| roster operations -> timers | pending create and kill timers hold references until the gateway answers |

## STRIDE Threat Register

Threat IDs are unique within the phase; this plan uses T-10-01 to T-10-04 and plan 10-02 continues from T-10-05.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
