<objective>
INT-02, frontend half 2 of 2 (Phase 8 criteria 1 and 3, UI side): the token dialog, logout with its full clearing list, and the two keyboard-first entry points. It builds on 08-03 (token store, transport, hello) and shares no file with the server plans of the same wave.

Locked decisions implemented here: D-02 (a password-masked dialog opened on `auth_failed` / auth required; no always-on settings field), D-03 (logout closes sockets, empties agent/roster/log stores, removes token and workspace data from storage, returns to the token dialog), D-04 (logout from a header menu item and a command-palette command, shown only when a token is set), D-05 (the UI never retries by itself after `auth_failed`).

Design decisions made here:
- Logout lives in a leaf module `src/services/session/logout.ts` that imports the stores and `agentSocket`; the stores and the transport never import it, so there is no import cycle (`agentStore` and `logBufferStore` already import `agentSocket`).
- Order matters (RESEARCH, Logout Clearing List): drop request promises WITHOUT rejecting, disconnect, then clear the token, then empty the stores, so no late frame or rejection repopulates what was just emptied. Each step runs in its own guard so one failure cannot skip the rest; `logout()` returns `{ complete }`.
- Storage sweep by prefix: every key beginning `agent-manager.` is removed from both storages. Nothing else in `src` uses browser storage today; Phase 13 (workspace persistence) must name its keys with that prefix, which makes "remove token and workspace data from storage" hold for future keys without editing logout (hand-off recorded in 08-05).
- The token dialog is opened by a small hook on connection state transitions (not a render-time check), so dismissing it with Escape does not make it reappear until the next real `auth_failed`.
- The Header has no menu today, so D-04's "header menu item" is a plain "Log out" button beside the connection chip (rendered only with a token); the palette command is UI-only (not a catalog operation, like `filter.focus`).
- Toasts (`NotificationToastManager`, React-local state holding agent names) are left alone: they expire within 5 s and carry no token or terminal output; recorded as accepted residue (T-08-22).
- Terminals unmount when the roster empties; the logout test renders the Workspace with agents, logs out and asserts no pane remains (verifies RESEARCH assumption A3; if a pane survives, the executor fixes the unmount path rather than weakening the test).

Existing tests edited here: `src/components/layout/__tests__/ConnectionBanner.test.tsx:92-97` ("shows auth_failed alert without a retry button" currently asserts no button at all; it becomes: exactly one button named "Enter token", and still no Retry / Reconnect), `src/keyboard/__tests__/commandsOperations.test.ts:21` (the UI-only allowlist gains `auth.logout`). Existing tests that must pass unchanged: the default-list assertions in `commands.test.ts` and `CommandPalette.test.tsx` (11 options), `Header.test.tsx` existing cases, every existing `agentStore*.test.ts`, `ShortcutHelp.test.tsx` (it reads `docs/KEYBOARD.md`).

Reversibility: `reversible` (new files and additive exports; git revert removes them; logout only deletes local state).
