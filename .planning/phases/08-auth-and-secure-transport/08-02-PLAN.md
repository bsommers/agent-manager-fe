<objective>
INT-02, gateway half 2 of 2 (Phase 8 criteria 1, 2, 3 and 4, server side): wire the 08-01 primitives into the running gateway. One plan owns both server hot files (`server/src/index.ts` and `server/src/http/apiRouter.ts`) because the router receives its auth dependencies from `bootstrap`; a second plan editing either would collide.

Locked decisions implemented here: D-05 (the server closes 4401, the FE stops), D-06 (shared throttle, 4429 and 429), D-07 (hello deadline, nothing but hello before auth, no pong pre-auth), D-08 (`/api` Bearer only, never in the URL), D-10 and D-12 (bind policy and "set means enforced, including loopback, unset means zero-config"), D-13 (the token travels in the hello body; hello_ack returns contract, auth and epoch; the server scrubs the token from every logged frame; one-way, settled by the user on 2026-11-12, and already pinned by the Phase 2 snapshot so no snapshot change is made).

Design decisions made here (recorded in PLANS-NOTES of 08-01, decisions 2 to 5):
- The confidentiality mechanism is registration order: `sessionManager.addClient` both joins the broadcast set and sends `agent:init_list`, so the gate decides whether it runs. `SessionManager.ts` is not edited. `hello_ack` is sent before `agent:init_list`.
- `agent:init_list` is sent once per connection (no re-send after `hello_ack` in no-token mode); 08-05 amends contract spec 2.5 accordingly.
- The legacy `GET /health` is exempt from auth by the spec, so it drops `agents` when a token is configured; `GET /api/health` returns `agents` only to a valid Bearer and counts a wrong Bearer as a failure.
- Only a wrong token counts toward the throttle (08-01 decision); missing token, malformed frames and the deadline close 4401 without counting.
- The gateway test configuration neutralizes `AGENT_MANAGER_TOKEN` and `AGENT_MANAGER_TRUST_PROXY` (`test.env` in `server/vitest.config.ts`), because `bootstrap(0, '127.0.0.1')` with no options reads the environment and an exported developer token would otherwise flip every existing test into auth mode.
- Startup logs one extra line stating whether authentication is enabled (never the token).

Existing tests edited here: `server/__tests__/lifecycle.test.ts` (the case at line 359, "accepts a hello and ignores it", now expects `hello_ack` then `pong`). Existing tests that must pass unchanged: `hardening.test.ts` (including :65-81), `index.test.ts` (its `'Invalid WebSocket message received:'` / `expect.any(Error)` assertions at :128), `httpApi.test.ts`, `rosterContract.test.ts`, `rosterEvents.test.ts`, `destructivePolicy.test.ts`, `killSession.test.ts`, `dispatch.test.ts` (hello stays a dispatch no-op because the handshake is handled in `index.ts` first).

Reversibility: `one-way` for the hello/hello_ack behavior (D-13, settled by the user; the shape was already locked in the snapshot by Phase 2); everything else here is `reversible` (git revert restores the unauthenticated gateway).

Coverage (source audit): criteria 1 to 4 server side, D-05 to D-08, D-10, D-12, D-13 and RESEARCH items "gate precedes addClient", "Bearer after Host and Origin guards", "health exemption", "shared bounded throttle", "JSON.parse snippet leak", "env leak guard" are covered here. Not planned here: the FE (08-03, 08-04), docs and nginx (08-05), in-gateway TLS (deferred), Origin check on `/api` and `ALLOW_REMOTE` (deferred).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| network client -> WebSocket upgrade and first frame | Attacker-controlled; unauthenticated until a valid hello |
| network client -> /api | Any host that can reach the port, including a hostile page via DNS rebinding or a cross-origin form |
| reverse proxy -> gateway | The proxy is trusted only when AGENT_MANAGER_TRUST_PROXY is on and the peer is loopback |
| gateway -> logs / responses | Anything printed or returned must be free of the token |
