Nothing here touches `server/src/index.ts` or `server/src/http/apiRouter.ts`; the running gateway behaves exactly as before until 08-02 lands.

Locked decisions implemented here: D-06 (constant-time compare, per-IP backoff in a bounded in-memory map), D-07 (the 5 s hello deadline and "nothing but hello before auth" as constants plus the pure verdict function), D-08 (the Bearer parse), D-10 (token required, with a minimum length, for a non-loopback bind; the existing refusal in `config.ts` is extended, not replaced), D-12 (unset means zero-config, set means enforced, including on loopback), D-13 (the hello body carries the token; hello_ack carries contract, auth and epoch; the scrubbing primitives that keep the token out of any logged frame).

Key finding that shapes the whole phase (verified from the repo): the wire contract already contains everything D-13 needs. `hello.token` (optional string, 0..512, no control characters), `hello.epoch`, and `hello_ack.{contract, epoch, auth.required, limits, backends}` exist in `packages/protocol` with fixtures (`hello-full`, `hello-ack-full`) and `CONTRACT_VERSION = 1`. Phase 8 is a behavior change on both sides, not a schema change, so this plan edits nothing under `packages/protocol` and `npm run contract:check` must report no diff.

Reversibility: `reversible` (new files plus additive exports in `config.ts`; git revert removes them; no wire or snapshot change).

Design decisions made here (all recorded in PLANS-NOTES below):
- Close codes 4401 and 4429 stay local constants in `handshake.ts` (and in the FE Transport); they are NOT added to `LIMITS` because that would change the surface snapshot's `limits` section. A drift test pins them to contract spec section 2.6.
- Only a wrong token (right shape, failed compare) counts toward the throttle. A missing token, a malformed or oversize frame, a non-hello first frame and the 5 s timeout close 4401 but are not "guesses", so a user who simply has not entered a token yet cannot lock themselves out.
- The pre-auth first frame is capped at 16 KiB (`MAX_PREAUTH_FRAME_BYTES`), far below the 1 MiB `maxPayload`, because a legitimate hello is a few hundred bytes (token at most 512 characters). Phase 11 revisits the cap if `resumeFrom` grows large.
- `hello_ack` advertises only what the gateway implements today: backend `local` with capabilities `terminal` and `broadcast` (dispatch.ts handles `agent:broadcast`; `agent:history` and `agent:approve` are routed to UNSUPPORTED, so `history` and `approve` are not claimed).

### Decisions needing user confirmation (defaults applied; override before execution if you disagree)

1. Keep the immediate `open` transition and add only a 3 s `hello_ack` watchdog when a token is set (FE: no ack means `auth_failed`, "gateway did not acknowledge authentication"). Contract spec 2.2 says `open` means "socket open and hello_ack received"; the plan amends the spec and records an ADR instead of delaying `open` (which would churn Transport, WsAdapter and agentSocket tests and add a 3 s delay for legacy gateways). Safe because the server registers a socket for broadcast only after auth.
2. `agent:init_list` is sent exactly once per connection, by `SessionManager.addClient`: immediately with no token, right after `hello_ack` with a token. It is NOT re-sent after `hello_ack` in no-token mode (spec 2.5 says "and again after hello_ack"; the plan amends it: the connect snapshot is already the single source of truth per ADR-011). `SessionManager.ts` stays untouched.
3. The legacy `GET /health` drops its `agents` field whenever a token is configured (it is exempt from auth, so it must not leak roster size); `GET /api/health` returns `agents` only with a valid Bearer, and a present-but-wrong Bearer there is a counted 401 (otherwise the field would be an unthrottled token oracle).
4. The proxy flag is named `AGENT_MANAGER_TRUST_PROXY` (1/true or 0/false, default off). When on and the socket peer is loopback, the throttle key is the last `X-Forwarded-For` entry; the nginx example overwrites the header.
5. Pre-auth first-frame cap: 16 KiB (close 4401). A per-IP cap on concurrent unauthenticated sockets is NOT included (the 5 s deadline plus heartbeat reaping bound the exposure; connection-flood protection is Phase 21 hardening).
6. Defaults (Claude's discretion per CONTEXT): throttle 5 wrong tokens per 60 s window, lock 60 s doubling per consecutive lockout up to 15 min, 10 000 tracked keys; token 24 to 512 printable ASCII characters, validated whenever the variable is set (also on loopback); an empty `AGENT_MANAGER_TOKEN=` counts as unset.
7. D-01 vs contract spec section 11 item 4 ("persisting the token is an explicit opt-in"): D-01 (memory plus `sessionStorage`) wins; 08-05 rewrites the spec sentence.
8. D-13 is rated one-way in CONTEXT; because the shape is already in the snapshot and fixtures, no snapshot change is needed and none is made (verified by `contract:check` in 08-01 and 08-02).
