Design decisions made here:
- The smoke runs the BUILT gateway as a child process (`server/dist/index.js`), because the in-process tests of 08-02 inject the token as an option and never exercise `process.env`, `resolveAuthToken` at start-up or the entry point's refusal exit. The token is generated per run with `crypto.randomBytes` and passed only through the child's environment (never argv, never printed); the child's output is captured and searched for the token.
- The smoke is committed (`server/scripts/smoke-auth.mjs`, plain ESM, not part of `tsc`) so QA can re-run it; it uses the `ws` package already in `server/` and Node's global `fetch`; it needs no dependency and picks a free port by binding port 0 first (it never uses 8088 and never touches any process it did not start).
- Spec corrections are prose-only. Tests parse the section 4.1 / 4.2 / 4.3 / 7 tables and the section 8 constants table, so those tables are not edited.
- Browser-side QA (dialog, logout, wss refusal in a real browser, a wrong token seen in the Network tab) cannot be run by an agent; it is written as a checklist and recorded PENDING-HUMAN in `08-EVIDENCE.md`, the same convention Phase 1 used.

Facts the tasks rely on (from 08-01 and 08-02, verify against the merged code before writing):
- Variables: `AGENT_MANAGER_TOKEN` (unset or empty: no auth; otherwise 24 to 512 printable ASCII characters, no spaces or control characters, validated even on loopback, never trimmed), `AGENT_MANAGER_TRUST_PROXY` (1/true or 0/false, default off), `HOST`, `PORT`, `ALLOWED_ORIGINS`. A non-loopback `HOST` without a valid token aborts start-up with a message naming `HOST` and `AGENT_MANAGER_TOKEN`.
- WS: with a token, nothing is sent until a valid hello arrives within 5 s; the answer is `hello_ack` (contract, epoch, auth.required, limits, backends) then `agent:init_list`; wrong token, missing token, malformed or oversize (over 16 KiB) first frame, a first frame that is not a hello and the deadline all close 4401 with the reason `unauthenticated`; only a wrong token counts toward the throttle; a throttled source is closed 4429 with reason `retry-after-ms=N`. Defaults: 5 wrong tokens per 60 s, lock 60 s doubling to 15 min, 10 000 tracked sources, IPv6 keyed by /64.
- HTTP: `Authorization: Bearer <token>` on every `/api` route except the minimal `GET /api/health`; 401 `UNAUTHENTICATED` with `WWW-Authenticate: Bearer`; 429 `RATE_LIMITED` with `Retry-After`; Host and Origin guards run first; the legacy `GET /health` drops `agents` when a token is set; a wrong Bearer on `/api/health` is a counted 401.
- FE: token in memory plus the `sessionStorage` key `agent-manager.token`; masked dialog on `auth_failed`; header `Log out` button and palette command while a token is set; `ws://` only for loopback; the connection chip/banner states are in RUNNING.md "Connection states".
- The Host guard accepts only loopback names and the configured `HOST` in the Host header, so a proxy must send `Host: 127.0.0.1:<gateway port>`; the WS upgrade and mutating `/api` calls also need the browser's origin in `ALLOWED_ORIGINS` (https origins are accepted).

Structure: a helper that finds a free port by listening on port 0 and closing; a helper that spawns node server/dist/index.js with a given environment (always setting NODE_ENV to production-like non-test, PORT, and removing any inherited AGENT_MANAGER_TOKEN unless given), collects stdout and stderr, and resolves once the listening line appears or the process exits; a per-run token from crypto.randomBytes encoded so it is at least 32 printable characters; the token goes into the child's environment only.

Checks, in order: (1) refusal: HOST 0.0.0.0 with no token exits non-zero and its output names AGENT_MANAGER_TOKEN and HOST; (2) refusal: a valid-looking but 10-character token exits non-zero and the output states the length rule without the value; (3) with a valid token on loopback the process listens; (4) WS wrong token: connect to the printed port, send a hello with a different token, expect close code 4401 and no frame received; (5) WS right token: expect the first frame hello_ack with auth.required true and a non-empty epoch, the second frame agent:init_list; (6) WS silent: connect and send nothing, expect close 4401 with no frame between 4.5 and 7 seconds; (7) HTTP: GET /api/agents without a header is 401, with the Bearer header is 200 (the header value is built in memory), /api/health without a header is 200 with no agents key, and legacy /health has no agents key; (8) throttle: five more wrong-token connections, then expect the next connection closed 4429 with a reason starting retry-after-ms=; (9) the captured stdout and stderr of every child, including the throttle child, contain neither the token nor the first 12 characters of it. Always kill children in a finally block and only children this script started; never use port 8088.

Ordering note: the throttle lock (check 8) is keyed on 127.0.0.1, so once it fires the auth middleware returns 429 for every /api request from that key. Check 8 must therefore run after all HTTP checks (check 7), and it runs in its own child on its own free port so it cannot affect checks 3 to 7. Check 9 must stay last because it reads the output of every child, including the throttle child. The 08-EVIDENCE section A results use these numbers.
