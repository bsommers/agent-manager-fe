<objective>
INT-02, frontend half 1 of 2 (Phase 8 criteria 1, 2, 3 and 4, transport side): the FE sends the `hello` that carries the token, understands `hello_ack`, stops cleanly on `auth_failed`, refuses plaintext `ws://` to non-loopback hosts, and holds the token without leaking it. This plan is the `src/services` layer plus the connection store; the dialog, logout and header entry points are 08-04. It is disjoint from 08-01 (server) and runs in the same wave.

Locked decisions implemented here: D-01 (token in memory plus `sessionStorage`, never elsewhere), D-02 (no build-time token; entry UI is 08-04), D-05 (on 4401 the transport goes to `auth_failed` and stops; no retries until a new token is submitted), D-11 (`ws://` only for loopback, otherwise a visible error and no fallback), D-13 (token in the hello body, `hello_ack` returns contract, auth and epoch; the token travels only on that path; one-way and already pinned by the Phase 2 snapshot, so no snapshot change).

Design decisions made here (PLANS-NOTES decisions 1 and 4 in 08-01):
- Keep the immediate `open` transition and add only a 3 s `hello_ack` watchdog for the token-set case. Spec 2.2 literally says `open` follows `hello_ack`; 08-05 amends the spec and records an ADR. The server registers the socket for broadcast only after authentication, so a brief "Connected" before a 4401 is a UX wart, not a safety issue, and no existing test churns.
- `hello` is sent only when the adapter is given a token getter (`createBackend` passes it in production); a bare `WsAdapter` or `Transport` (as in the existing tests) sends nothing extra.
- 4429 is handled as a normal reconnect with a delay floor from `retry-after-ms=N` in the close reason, so the spec's "back off at least the advertised delay" holds without a new state.
- Close codes are local constants in `Transport.ts` (not in the protocol package, which would change the snapshot's limits section) with a drift test against the spec text.
- Rejecting credentials, query strings and fragments in `VITE_BACKEND_URL` / `VITE_WS_URL` closes the one path by which a token could reach `new WebSocket(url)` (`VITE_WS_URL` is used verbatim today).

Existing tests edited here: `src/services/__tests__/backend.test.ts:21-32` (fixtures use `ws://other:1234/ws`, `http://a:1` and `ws://b:2/ws`; under D-11 those become configErrors, so the fixtures change to loopback hosts or `wss://` and refusal cases are added) and `src/store/__tests__/connectionStore.test.ts:19-31` (the snapshot literals gain `epoch` and `authRequired`). Existing tests that must pass unchanged: all other Transport and WsAdapter cases, `agentSocket.test.ts`, `ConnectionBanner.test.tsx`, `ConnectionStatusChip.test.tsx`.

Reversibility: `reversible` for everything but the hello shape (D-13, one-way, already pinned): new files plus additive options; git revert restores today's behavior.
