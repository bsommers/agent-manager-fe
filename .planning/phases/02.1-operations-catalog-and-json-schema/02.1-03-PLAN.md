<objective>
Derive the palette entries of the three operation commands from the operations catalog built by plan 02.1-02, make a test fail when the palette and the catalog disagree in either direction, and document the catalog in contract spec section 4.3 and the package README, with a test that reads the spec table and fails when it drifts from OPERATIONS (INT-12, ROADMAP Phase 2.1 criterion 2: the palette and documentation half; the WS, HTTP and MCP half is plan 02.1-02).

Purpose: the FE command palette is the one surface a user touches directly; a destructive operation must never become a palette command by accident, and a new operation with a palette binding must not be able to ship without its command.
Output: palette derivation in `src/keyboard/commands.ts`, `commandsOperations.test.ts`, a spec cross-check test in `operations.test.ts`, contract spec section 4.3, README update.

Split note: this plan is the former Task 3 of 02.1-02, split into wave 6 because 02.1-02 was the larger plan; it depends only on the exports of 02.1-02 (OPERATIONS, OperationName, PaletteOperationName, surfaceIdentities, checkSurfaceCoverage, all exported through `packages/protocol/src/index.ts`).

Design decisions (planner discretion, no CONTEXT.md exists for this phase):
- The palette keeps its three operation commands under their existing ids (agent.new, broadcast.open, search.open) so titles, order, hints and the existing keyboard tests do not change; UI-only commands (filter, help, layouts, go to) carry no operation and are matched by an explicit pattern in the test.
- Catalog titles and UI strings stay in the FE: the catalog holds only the palette command id; `OPERATION_COMMANDS` in commands.ts is a record keyed by the type of palette-bound operation names, so a new palette binding without a command is a compile error.

Ownership and ordering (wave 6): this plan owns `src/keyboard/commands.ts` with its new test `src/keyboard/__tests__/commandsOperations.test.ts`, the spec cross-check test added to `packages/protocol/src/__tests__/operations.test.ts` (created by 02.1-02), the contract spec and `packages/protocol/README.md`. Plan 02.1-02 no longer touches any of these files, and plan 05-04 must not edit `src/keyboard/commands.ts` (owned here). It does not touch root `package.json` or lockfiles (plan 05-04 owns them), `packages/protocol/{SCHEMA.md,contract.schema.json,scripts/**,src/jsonschema.ts}` (plan 02.1-01, wave 5, merged before wave 6 starts) or anything under `server/`. No package is installed.
