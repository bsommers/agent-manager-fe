<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| keyboard input -> destructive action | A stray Enter or Space on a freshly opened confirmation could confirm a fan-out of a destructive command |
| window keydown listener -> terminals | A global Tab/Escape listener could swallow keys intended for xterm when no modal is open |

## STRIDE Threat Register

Threat IDs are unique within the phase; this is the first Phase 5 plan.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Tampering | DestructiveSafetyModal initial focus | medium | mitigate | Initial focus on Cancel, Escape maps to cancel, no backdrop dismissal; asserted by test so Confirm Broadcast can never be the default focus target |
| T-05-02 | Denial of Service | useModalFocus window listener | low | mitigate | The listener is registered only while a modal is open and removed on close and unmount (asserted); only the topmost modal handles keys |
| T-05-03 | Information Disclosure | aria labels and descriptions | low | accept | Labels are static copy; the destructive command text stays in the existing visible block and is not duplicated into aria attributes |
| T-05-SC | Tampering | npm/pip/cargo installs | high | accept | No packages installed; the focus trap is hand-written and user-event is already a devDependency |
</threat_model>
