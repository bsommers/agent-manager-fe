<objective>
Command palette and shortcut help: UX-08 success criterion 1 ("Ctrl+K command palette reaches agents, layouts, broadcast and search; a shortcut help overlay lists every binding").

Purpose: make the whole app operable without a mouse. Today search state lives in Header, add-agent state in App and the broadcast bar state in Toolbar, so nothing outside those components can open them; xterm also swallows every Ctrl-modified key, so a global chord can never fire while a terminal (where keyboard users spend their time) has focus. This plan adds one shared UI store, one shortcut registry, a palette, a help overlay and the terminal pass-through.

Output: `src/store/uiStore.ts`, `src/keyboard/{shortcuts,hooks,commands}.ts`, `CommandPalette.tsx`, `ShortcutHelp.tsx`, edits to Header, Toolbar, App and TerminalView, `docs/KEYBOARD.md`, and tests for all of it.

Cross-plan contract with 05-03 (pane chrome, same wave, disjoint files; neither plan imports the other): the registry rows in group "Panes" document what 05-03 implements and pins by test: with a pane title bar focused (accessible name "Move pane <agent name>"), Arrow keys move it 10 px and Shift+Arrow 50 px; with the resize handle focused ("Resize pane <agent name>"), Right/Down grow and Left/Up shrink the pane by 10 px, 50 px with Shift. These values must not be changed here without changing 05-03.

No Phase 5 CONTEXT.md exists, so there are no locked decisions; choices below are planner discretion and are fixed here so the executor does not re-decide them: chords are matched on `event.key` only (layout-correct; the old Header handler also accepted `event.code`, which fires on the physical key position and would hijack Ctrl+E on Colemak); Alt must not be held (AltGr is Ctrl+Alt on Windows); palette hosts no destructive commands; no new dependency (fuzzy search is a small hand-written ranker).

Why Header hosts the global shortcut hook: Header is mounted whenever the shell is, and the existing contract that Ctrl+Shift+F works with Header rendered alone (GlobalSearchModal.test.tsx) must keep holding.
</objective>

- xterm 5.5 registers its textarea keydown listener in the capture phase and, for every Ctrl-modified key it forwards to the program, cancels the event (preventDefault and stopPropagation), so a window listener never sees Ctrl+K from inside a terminal. `Terminal.attachCustomKeyEventHandler(fn)` skips xterm's own handling and cancelling when `fn` returns false, and the event then bubbles normally.
